이 매뉴얼은 학습자가 Codyssey에서 공개 API 키를 발급받아 Claude Code·Cursor 같은 외부 도구나 자체 코드에서 Codyssey AI를 사용하는 방법을 안내합니다.

1. 공개 API란

2. API 콘솔 접속

로그인 후 학습자 사이트에서
/public-api-console
경로로 접속하면 API 콘솔이 열립니다. 콘솔은 API 키 · 사용량 · 문서 세 개 탭으로 구성되고, 상단 카드에서 활성 키 수, 이번 달 사용 토큰, 잔여 토큰을 한눈에 볼 수 있습니다.
서비스 메뉴에서의 진입 위치는 운영 배포 시 확정 예정입니다. 현재 QA 환경에서는 위 경로로 직접 접속합니다.
API 콘솔 — API 키 탭. 상단에 활성 키 / 이번 달 사용 토큰 / 잔여 토큰 카드가 표시됩니다.
ALT

3. API 키 발급

3-1. 발급 절차

API 키 탭에서 [+ 키 발급] 버튼을 누릅니다.
키를 구분할 라벨을 입력하고, API 호환 방식(Anthropic 또는 OpenAI)을 선택합니다.
[키 발급]을 누르면 키 원문이 표시됩니다.
키 발급 모달 — 라벨과 API 호환 방식(Anthropic/OpenAI)만 입력하면 됩니다. 만료일·IP 제한 등은 기본 정책이 적용됩니다.
ALT
키 원문은 발급 직후 한 번만 표시됩니다. 화면을 닫으면 다시 볼 수 없으니 즉시 안전한 곳에 복사해 두세요. 분실하면 키를 폐기하고 새로 발급해야 합니다.
발급 완료 — “이 값은 한 번만 표시됩니다.” (예시 화면의 키 원문은 가림 처리했습니다)
ALT

3-2. 키 정책

호환 방식별로 각 1개(Anthropic 1개 + OpenAI 1개)까지 발급할 수 있습니다.
서버에는 키의 해시와 앞·뒤 일부만 저장되며, 원문은 저장되지 않습니다.
키 재표시 허용 여부, 만료 정책, 요청 속도 제한(rate limit) 등 세부 정책은 협의 중이며 확정 시 안내됩니다.
발급이 거부되는 경우 — 소속 기관에 해당 provider(Anthropic/OpenAI)의 LLM 키가 등록되어 있지 않으면 “항상 실패하는 키”가 만들어지는 것을 막기 위해 발급이 차단되고 화면에 사유가 표시됩니다. 이 경우 기관 운영자에게 문의하세요.

4. 키 수정과 폐기

키 목록에는 라벨, 키 식별자(앞부분과 끝 4자리), 상태, 호환 방식, 마지막 사용 시각이 표시되고 작업 열의 아이콘으로 수정(연필)·폐기(휴지통)를 실행합니다.
내 API 키 목록 — 작업 열의 연필 아이콘은 수정, 휴지통 아이콘은 폐기입니다.
ALT

4-1. 키 수정

연필 아이콘을 누르면 API 키 정책 창에서 라벨과 호환 방식을 변경할 수 있습니다. 키 원문은 다시 표시되지 않습니다.
API 키 정책 — 라벨·호환 방식 변경.
ALT

4-2. 키 폐기

휴지통 아이콘 → 확인 창에서 [폐기]를 누르면 즉시 무효화됩니다. 폐기는 되돌릴 수 없으며, 필요하면 새로 발급해야 합니다.
폐기 확인 창.
ALT
폐기 후 — 상태가 ‘폐기’로 바뀌고 활성 키 수가 줄어듭니다.
ALT

5. 사용량 조회

사용량 탭에서는 기간·키·API 종류·모델·상태로 필터링해 호출 수, 토큰, 차감 토큰, 잔여 토큰을 확인할 수 있습니다. 차트는 키 / 모델 / API 기준으로 전환됩니다. 하단 최근 호출 목록에서는 개별 호출 이력을 확인하고, 완료된 영상은 다운로드할 수 있습니다.
사용량 탭 — 필터, 합계 카드, 사용량 차트, 최근 호출 목록.
ALT
모델마다 차감 가중치가 달라 실제 사용 토큰과 차감 토큰이 다를 수 있습니다. 가중치는 문서 탭의 “모델별 차감 가중치” 표에서 확인하세요.

6. 문서 탭 활용

문서 탭은 공개 API 사용에 필요한 정보를 모두 담고 있습니다.
Endpoint reference — 프로토콜별 전체 엔드포인트 목록
모델별 차감 가중치 — 모델·모달리티별 차감 배수와 사용 가능 여부
코드 예제 — 5개 카테고리(텍스트 OpenAI / 텍스트 Anthropic / 이미지 / 음성 / 영상) × 3개 언어(cURL / JavaScript / Python)
도구 설정 — Claude Code · Cursor · Continue 연동 설정법
문서 탭 전체 구성 — Endpoint reference, 모델별 차감 가중치, 코드 예제, 도구 설정.
ALT
코드 예제 ‘이미지’ 카테고리 —
response_format: "b64_json"
기준 예제와 저장 방법까지 안내합니다.
ALT
코드 예제 ‘영상’ 카테고리 — 생성 → 상태 확인(폴링) → 다운로드의 비동기 흐름을 세 언어로 제공합니다.
ALT

7-3. 이미지·음성 — 반드시 b64_json으로 받기

응답에 포함되는
url
(이미지)·
audioUrl
(음성)은 웹 로그인 세션 전용 경로입니다. API 키로 열면 401이 발생합니다. 파일이 필요하면 요청에
response_format: "b64_json"
을 지정해 base64 원본을 응답으로 직접 받으세요.
POST /api/v1/images { "model": "gpt-image-1-mini", "prompt": "흰 배경의 파란 원", "size": "1024x1024", "response_format": "b64_json" } → 응답의 images[0].b64_json 을 디코딩해 파일로 저장
​
음성도 동일하게
response_format: "b64_json"
을 지정합니다. 이때
format
은 오디오 코덱(mp3 등),
response_format
은 전달 방식으로 서로 다른 파라미터입니다.

7-4. 영상 — 생성부터 다운로드까지

POST /api/v1/videos
— 생성 요청, 작업 ID 반환
GET /api/v1/videos/{id}
— 상태 폴링 (완료까지 반복)
GET /api/v1/videos/{id}/download
— 완료된 mp4를 API 키로 직접 다운로드
상태 응답의
resultUrl
은 웹 세션 전용이므로 코드에서는 반드시
downloadUrl
(
/api/v1/videos/{id}/download
)을 사용하세요.
지원하지 않는
resolution
을 보내면 400 응답에 사용 가능한 값이 함께 안내됩니다. 지원 값은 운영 설정에 따라 변할 수 있으므로 이 안내를 1차 기준으로 삼으세요.
→ HTTP 400 { "errors": { "code": "invalid_media_request", "message": "지원하지 않는 resolution 입니다. model=veo-3.1-fast, 요청값=1080p, 사용 가능=720p" } }
​

9. 보안 주의사항

키 원문을 코드 저장소, 채팅, 문서에 남기지 마세요. 환경변수나 시크릿 관리 도구를 사용하세요.
키가 유출됐다고 판단되면 즉시 폐기하고 새로 발급하세요.
키는 본인 학습 용도로만 사용하세요. 모든 호출은 감사 로그로 기록되며 운영자가 조회할 수 있습니다.
생성한 콘텐츠(프롬프트·응답 포함)는 콘텐츠 이력으로 저장되어 기관 운영자가 확인할 수 있습니다.
